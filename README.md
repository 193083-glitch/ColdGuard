# ColdGuard – Real-Time Cold-Chain Risk Intelligence

## Project Overview

ColdGuard is an end-to-end streaming analytics solution designed to identify developing cold-chain risks in real time.

The system monitors temperature-sensitive shipments using sensor events and combines them with product, vehicle, and shipment information. Incoming sensor readings are evaluated against product-specific temperature and humidity requirements, and high-risk conditions generate alerts.

The objective is to identify developing risks early enough for logistics teams to investigate and intervene.

## Business Problem

Temperature-sensitive products such as dairy, fresh produce, meat, seafood, frozen foods, pharmaceuticals, and ready-to-eat foods must remain within appropriate environmental conditions during transportation.

If temperature problems are discovered only after delivery, valuable inventory may already be at risk.

ColdGuard uses streaming analytics so sensor events can be processed as they arrive instead of waiting for batch analysis.

The system helps answer questions such as:

- Which shipments are currently at elevated risk?
- Which routes experience more temperature excursions?
- Does risk vary by time of day?
- Which product categories experience more excursions?
- Which vehicles show weaker cold-chain performance?
- How much inventory value is associated with high-risk shipments?
- Are excursions associated with door openings or refrigeration problems?

## Data

ColdGuard uses five MongoDB collections:

### 1. Products

Contains product information and acceptable temperature/humidity ranges.

### 2. Vehicles

Contains refrigerated vehicle information, including refrigeration efficiency and maintenance information.

### 3. Shipments

Contains shipment, route, quantity, value, departure, arrival, and priority information.

### 4. Sensor Events

Contains streaming telemetry such as:

- Temperature
- Humidity
- Door status
- Refrigeration status
- Vehicle speed
- GPS location
- Ambient temperature
- Battery voltage
- Signal strength
- Engine status

### 5. Alerts

Contains risk alerts generated by the streaming risk engine.

## Dataset Scale

The project uses a large simulated operational dataset:

- 1,000 products
- 1,500 vehicles
- 100,000 shipments
- 460,000+ sensor events

The sensor data contains temporal variation, route movement, environmental conditions, refrigeration status, door status, and temperature fluctuations.

## Kafka

Kafka topic:

`coldchain.sensor.events`

Producer:

`kafka/producer.py`

Consumer:

`kafka/consumer.py`

The producer publishes sensor events to Kafka, while the consumer processes the incoming events through the risk engine.

## Risk Engine

Implemented in:

`processing/risk_engine.py`

The risk engine evaluates incoming sensor events against product-specific environmental requirements.

Risk factors include:

- Temperature outside the permitted range
- Humidity outside the permitted range
- Door open condition
- Refrigeration not operating
- Engine not running

Risk levels:

- NORMAL
- WATCH
- HIGH
- CRITICAL

High and critical conditions can generate alerts.

## Alert Engine

Implemented in:

`processing/alert_engine.py`

Generated alerts contain information such as:

- Shipment
- Vehicle
- Product
- Severity
- Risk score
- Temperature
- Threshold
- Risk reasons
- Probable cause
- Inventory value at risk

A temperature excursion is treated as a risk signal and does not automatically mean that inventory has spoiled.

## Streamlit Dashboard

Implemented in:

`dashboard/app.py`

The dashboard provides:

- Executive KPIs
- Temperature trends
- Route and time-of-day analysis
- Product category risk
- Vehicle performance
- Shipment delay and inventory exposure
- Operating-condition analysis
- Alert intelligence
- Pipeline status

The dashboard supports decisions such as identifying high-risk shipments, investigating problematic routes or vehicles, and prioritizing interventions.
